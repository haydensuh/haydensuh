# 프로덕트 디자이너가 업무에 AI를 활용하는 방법

**디자인부터 개발까지, 직접 코드 수정하는 디자이너가 AI로 개선하는 워크플로우**

_프로덕트 디자이너로서 일상 업무에 AI를 도입하며 배운 것들 —  
이슈 파악부터 개발자 핸드오프까지, AI가 어떻게 업무 효율을 높였는지 공유합니다._

---

프로덕트 디자이너의 업무는 생각보다 넓습니다. 사용자 문제를 파악하고, 솔루션을 설계하고, 개발자와 소통하며, 문서를 정리하는 것까지. 각 단계마다 시간이 걸리고, 때로는 반복적인 작업도 많습니다.

AI 도구들이 등장하면서 이런 업무 흐름을 개선할 수 있는 기회가 생겼습니다. ChatGPT, Cursor, GPT Atlas 등 다양한 AI 도구를 활용해 실제 업무 프로세스를 어떻게 개선했는지 공유합니다.

---

- 한눈에 파악할 수 있는 형태로 정리된 결과를 받아 빠르게 컨텍스트 파악

이렇게 하면 수 시간 걸리던 이슈 파악 작업을 몇 분 안에 완료할 수 있습니다.

이슈 파악이 끝나면 PRD(Product Requirements Document)를 작성해야 합니다. 하지만
처음부터 모든 내용을 작성하는 것은 부담스럽습니다.

**해결 방법**

- 1단계에서 정리한 내용을 바탕으로 ChatGPT에 PRD 초안 작성 요청
- 구조와 큰 틀은 AI가 만들어주고, 세부 내용과 비즈니스 맥락은 직접 수정
- 반복적인 템플릿 작성 시간을 절약하고, 핵심 내용에 집중

AI가 만든 초안은 완벽하지 않지만, 시작점을 제공해주기 때문에 전체적인 작성 속도가 크게 향상됩니다.

디자인 툴로 화면을 그리는 것도 중요하지만, 때로는 실제로 동작하는 프로토타입이 필요할 때가 있습니다. 특히 개발자와 소통할 때는 코드로 된 초안이 더 명확할 수 있습니다.

**해결 방법**

- Cursor에 위에서 정리한 내용들을 기반으로 초안 디자인 요청
- "이 PRD와 레퍼런스를 바탕으로 프론트엔드 초안을 만들어줘"라고 지시
- 백엔드 코드는 최대한 건드리지 않고, 디버깅 가능한 수준으로만 수정
- 프론트엔드 코드 위주로 작업하여 빠르게 프로토타입 완성

이렇게 하면 Figma로 그린 정적인 디자인보다 훨씬 구체적인 피드백을 받을 수 있습니다.

## 5. 디벨롭 - 원하는 방향으로 점진적 개선

초안이 완성되면 본격적으로 디벨롭 단계로 들어갑니다. 이때는 내가 원하는 방향을 명확히 전달하고, AI가 코드를 수정하도록 합니다.

**해결 방법**

- "이 부분을 이렇게 바꿔줘", "이 기능을 추가해줘" 등 수정사항 요청
- 단, 추상적으로 요청하기보다 백엔드 로직을 먼저 분석하고 그에 맞는 수정사항 전달
- Cursor를 통해 백엔드 로직도 파악할 수 있어 전체적인 구조 이해 가능
- 점진적으로 개선해가며 원하는 결과물에 도달

AI가 코드를 수정하는 과정을 보면서, 백엔드 구조도 자연스럽게 이해하게 됩니다.

이때 cursor의 명령어 설정이 작업 속도를 더 빠르게 만들어주는데, 저는 아래와 같이 설정해두었습니다.

```bash
/branch

1. 현재 브랜치에서의 변경사항을 git stash 하고
2. git checkout master 를 실행해서 master 브랜치로 갔다가
3. g farbm 을 실행해서 최신 mater 브랜치를 rebase 하고
4. git checkout -b suhhj-00000로 브랜치명을 만드는데
5. 이때 suhhj-00000 의 숫자는 난수로 아무렇게나 지정해줘
```

```bash
/prepare-pr

다음 단계를 **순서대로 정확히 수행**하세요.

### 1. 현재 변경사항 확인

- `git status` 와 `git diff`를 사용해 현재 브랜치의 변경사항을 파악합니다.

### 2. 브랜치명 제안

- 변경된 파일과 코드 내용을 기반으로
  **작업의 핵심을 가장 잘 드러내는 브랜치명**을 하나 제안합니다.
- 브랜치명 규칙:

  - 작업 목적이 명확해야 함 (feature / fix / refactor / ux 등 맥락 드러나게)
  - kebab-case 사용

### 3. 사용자 확인 요청

- 제안한 브랜치명을 사용자에게 보여주고,
- `AskUserQuestion`을 사용해 **해당 브랜치명을 사용할지 확인**을 요청합니다.

### 4. 브랜치명 변경

- 사용자가 승인한 브랜치명으로 현재 브랜치명을 변경합니다.

### 5. 스테이징 및 커밋

- 모든 변경사항을 스테이징합니다.
- 변경 내용을 정확히 반영한 커밋 메시지를 작성해 커밋합니다. (이때 커밋메세지는 한국어로 작성합니다.)

### 6. 원격 브랜치로 push

- 새 브랜치를 원격 저장소에 push 합니다.

### 7. PR 생성

- PR을 생성합니다.
- PR 작성 시 다음을 반드시 지킵니다:

  - assignee: `suhhj93`
  - PR 제목과 본문은 변경사항을 명확히 설명할 것
  - 저장소의 `CLAUDE.md`에 정의된 **PR 가이드라인을 준수**할 것

### 8. 결과 반환

- 생성된 PR의 URL을 최종 결과로 반환합니다.

### 주의사항

- 커밋 메시지는 변경사항을 정확히 반영해야 합니다.
- PR 제목과 본문은 리뷰어가 맥락을 이해할 수 있을 정도로 충분히 설명해야 합니다.
- 모든 과정은 순서를 건너뛰지 말고 수행합니다.

```

프로토타이핑이 완료되면 관련 문서를 정리해야 합니다. 정책서, 가이드 문서, 또는 팀 내 공유 문서 등이 필요할 때가 많습니다.

**해결 방법**

- Cursor에 "디벨롭한 내용을 정리된 형태의 정책서로 작성해줘"라고 요청
- 구조화된 문서 형태로 자동 생성
- 필요에 따라 추가 수정 및 보완

일관된 형식의 문서를 빠르게 작성할 수 있어 팀 내 소통이 원활해집니다.

## 7. 개발자 핸드오프 - 정리된 내용으로 효율적 전달

<img
  src="https://res.cloudinary.com/hazelsuh-site/image/upload/v1767340854/TV_-_15_b3tbmk.png"
  alt=""
  style={{
    width: '100%',
    height: 'auto',
    backgroundColor: 'rgba(0, 0, 0, 0.02)',
    borderRadius: '8px',
  }}
/>

마지막으로 개발자에게 작업 내용을 전달해야 합니다. 이때 구두 소통도 중요하지만, 문서화된 내용이 있으면 훨씬 수월합니다.

**해결 방법**

- 위에서 정리한 모든 내용(PRD, 디자인 초안, 개발 내용, 문서)을 종합해서 핸드오프 문서 작성
- Cursor에 "이 내용들을 개발자 핸드오프용으로 정리해줘"라고 요청
- 구두 소통 전에 미리 문서를 공유하여 대화의 효율성 향상

물론 이때 구두로 사전 소통을 하는 것이 훨씬 수월하지만, 문서가 있으면 대화의 맥락을 빠르게 공유할 수 있습니다.

## 마무리하며

프로덕트 디자이너의 업무는 다양하고 복잡합니다. AI 도구들을 적절히 활용하면 이런 복잡함을 줄이고 더 가치 있는 작업에 시간을 투자할 수 있습니다.

물론 AI가 만든 결과물이 항상 완벽한 것은 아닙니다.

하지만 중요한 것은 AI를 어떻게 활용할지 그리고 어떤 부분에 AI를 도입할지 판단하는 것이며 각자의 업무 환경과 프로세스에 맞게 AI를 도구로 활용하는 방법을 찾아가는 것이 중요하다고 생각합니다.
