# 프로덕트 디자이너가 업무에 AI를 활용하는 방법

**디자인부터 개발까지, AI로 워크플로우 개선하기**

_프로덕트 디자이너로서 일상 업무에 AI를 도입하며 배운 것들 —  
이슈 파악부터 개발자 핸드오프까지, AI가 어떻게 업무 효율을 높였는지 공유합니다._

---

프로덕트 디자이너의 업무는 생각보다 넓습니다. 사용자 문제를 파악하고, 솔루션을 설계하고, 개발자와 소통하며, 문서를 정리하는 것까지. 각 단계마다 시간이 걸리고, 때로는 반복적인 작업도 많습니다.

AI 도구들이 등장하면서 이런 업무 흐름을 개선할 수 있는 기회가 생겼습니다. ChatGPT, Cursor, GPT Atlas 등 다양한 AI 도구를 활용해 실제 업무 프로세스를 어떻게 개선했는지 공유합니다.

## 4. 초안 디자인 - 코드로 빠르게 프로토타입 만들기

디자인 툴로 화면을 그리는 것도 중요하지만, 때로는 실제로 동작하는 프로토타입이 필요할 때가 있습니다. 특히 개발자와 소통할 때는 코드로 된 초안이 더 명확할 수 있습니다.

**해결 방법**

- Cursor에 위에서 정리한 내용들을 기반으로 초안 디자인 요청
- "이 PRD와 레퍼런스를 바탕으로 프론트엔드 초안을 만들어줘"라고 지시
- 백엔드 코드는 최대한 건드리지 않고, 디버깅 가능한 수준으로만 수정
- 프론트엔드 코드 위주로 작업하여 빠르게 프로토타입 완성

이렇게 하면 Figma로 그린 정적인 디자인보다 훨씬 구체적인 피드백을 받을 수 있습니다.

**해결 방법**

- "이 부분을 이렇게 바꿔줘", "이 기능을 추가해줘" 등 수정사항 요청
- 단, 추상적으로 요청하기보다 백엔드 로직을 먼저 분석하고 그에 맞는 수정사항 전달
- Cursor를 통해 백엔드 로직도 파악할 수 있어 전체적인 구조 이해 가능
- 점진적으로 개선해가며 원하는 결과물에 도달

AI가 코드를 수정하는 과정을 보면서, 백엔드 구조도 자연스럽게 이해하게 됩니다.

이때 cursor의 명령어 설정이 작업 속도를 더 빠르게 만들어주는데, 저는 아래와 같이 설정해두었습니다.

```bash

1. 현재 브랜치에서의 변경사항을 git stash 하고
2. git checkout master 를 실행해서 master 브랜치로 갔다가
3. g farbm 을 실행해서 최신 mater 브랜치를 rebase 하고
4. git checkout -b suhhj-00000로 브랜치명을 만드는데
5. 이때 suhhj-00000 의 숫자는 난수로 아무렇게나 지정해줘
```

```bash
/prepare-pr

다음 단계를 **순서대로 정확히 수행**하세요.

### 1. 현재 변경사항 확인

- `git status` 와 `git diff`를 사용해 현재 브랜치의 변경사항을 파악합니다.

### 2. 브랜치명 제안

- 변경된 파일과 코드 내용을 기반으로
  **작업의 핵심을 가장 잘 드러내는 브랜치명**을 하나 제안합니다.
- 브랜치명 규칙:

  - kebab-case 사용

### 3. 사용자 확인 요청

- 제안한 브랜치명을 사용자에게 보여주고,

  - 저장소의 `CLAUDE.md`에 정의된 **PR 가이드라인을 준수**할 것

### 8. 결과 반환

- 생성된 PR의 URL을 최종 결과로 반환합니다.

### 주의사항

- 모든 과정은 순서를 건너뛰지 말고 수행합니다.
```

## AI 활용의 핵심 원칙

위의 7가지 단계를 실전에서 적용하다 보면, AI와 더 효과적으로 소통하는 방법에 대한 인사이트를 얻을 수 있습니다. 몇 가지 중요한 원칙들을 공유합니다.

### 1. AI를 리뷰어로 활용하기

복잡한 디자인이나 정책 결정을 할 때, AI를 대체자보다는 **리뷰어로 활용**하는 것이 효과적입니다. 특히 디자이너가 정책 결정을 하고 엔지니어나 사업팀과 소통해야 할 때 도움이 됩니다.

**활용 방법**

- AI가 어떤 역할을 맡을지 (사업부 혹은 엔지니어 등)을 먼저 입력
- "내 주장의 전제를 찾고, 전제의 문제점을 말해줘"라고 요청
- 다양한 관점(엔지니어, 사업팀, 사용자 등)에서 논리적 허점을 찾아내도록 활용

이렇게 하면 내가 놓친 부분이나 논리적 모순을 사전에 발견할 수 있습니다.

### 2. Context를 한번에 많이 넘기기

AI가 정확한 결과를 내기 위해서는 충분한 맥락(Context)이 필요합니다. 텍스트, 사진, 관련 문서 등을 **최대한 한번에 많이 넘기는 것**이 중요합니다.

**이유**

- Context 없이 뜬금없이 질문하면 AI가 전체 맥락을 파악하지 못함
- 순차적으로 정보를 전달하면 AI가 국소적으로만 판단하게 됨
- 한번에 모든 정보를 제공하면 AI가 전역적으로 판단하고 논리적 모순도 찾아냄
- 단, Cursor는 코드베이스를 인덱싱하고 있어서 Context가 자동으로 포함됨

### 3. 순차적 프롬프팅 vs 일괄 프롬프팅

AI에게 정보를 전달하는 방식에 따라 결과의 품질이 크게 달라집니다.

**순차적 전달 (Sequential)**

- **비유** : 요리사에게 재료를 하나씩 던져주며 요리하라고 함
- **AI의 사고** : 국소적 판단 (이 재료로 뭘 하라는 거지?)
- **문제점** : 앞뒤 말이 달라도 모르고 지나침, 지시할수록 코드가 꼬이거나 스타일이 깨짐

**일괄 전달 (Holistic/Batch)**

- **비유** : 미장플라스(Mise en place) / 모든 재료를 손질해두고 요리 시작
- **AI의 사고** : 전역적 판단 (아, 이 재료들을 조합해서 이걸 만드는구나.)
- **장점** : A문서와 B문서의 논리적 모순을 찾아냄, 처음부터 완성도 높은 결과물 도출

**실전 팁**

- PRD, 레퍼런스, 기존 코드, 관련 문서 등을 한번에 전달
- "이 모든 내용을 종합해서..."로 시작하는 프롬프트 사용
- 단계별로 나누기보다 전체 맥락을 한번에 제공

### 4. Human in the Loop - 모든 수정은 확인하고 넘기기

AI가 생성한 결과물을 그대로 사용하기보다는, **모든 수정사항을 확인하고 넘기는 것**이 중요합니다.

**이유**

- AI가 만든 코드나 문서에 논리적 오류나 비즈니스 맥락이 빠진 부분이 생각보다 많음
- 각 단계에서 사람이 검토하고 수정해야 최종 품질이 보장됨
- 특히 정책 결정이나 중요한 비즈니스 로직은 반드시 사람이 최종 확인

**실전 팁**

- AI가 생성한 코드는 실행 전에 반드시 검토
- 문서는 비즈니스 맥락과 사용자 경험 관점에서 재검토
- 팀 내 공유 전에 최종 확인 절차 거치기

## AI를 활용한 업무 프로세스 개선의 핵심

핵심은, AI가 모든 것을 대신해주는 것이 아니라 **반복적이고 시간이 걸리는 작업을 효율화**하는 것입니다.

각 단계에서 AI가 초안을 만들고 저는 그 위에서 비즈니스 맥락과 사용자 경험을 고려한 판단을 내립니다. AI가 빠르게 정보를 수집하고 정리해주면 저는 더 중요한 결정에 집중할 수 있게 됩니다.

---

## 마무리하며

프로덕트 디자이너의 업무는 다양하고 복잡합니다. AI 도구들을 적절히 활용하면 이런 복잡함을 줄이고 더 가치 있는 작업에 시간을 투자할 수 있습니다.

물론 AI가 만든 결과물이 항상 완벽한 것은 아닙니다.

하지만 중요한 것은 AI를 어떻게 활용할지 그리고 어떤 부분에 AI를 도입할지 판단하는 것이며 각자의 업무 환경과 프로세스에 맞게 AI를 도구로 활용하는 방법을 찾아가는 것이 중요하다고 생각합니다.
